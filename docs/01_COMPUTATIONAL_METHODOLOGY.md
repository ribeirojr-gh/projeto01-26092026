# Computational Methodology & First-Principles Architecture

## 1. Density Functional Theory Engine
All quantum mechanical calculations are performed using the **GPAW** code (version 25.7.0), interfaced through the **Atomic Simulation Environment (ASE)** (version 3.29).

### 1.1 Representation & Basis Set
* **Plane-Wave (PW) Mode:** Calculations utilize uniform kinetic energy cutoffs:
  * Production: $E_{\mathrm{cut}} = 1400\text{ eV}$
  * High-precision benchmark/validation: $E_{\mathrm{cut}} = 1600\text{ eV}$
* The plane-wave mode is chosen for its complete variational freedom, absence of Pulay stress during cell relaxation, and consistent convergence across disparate atomic species (light carbon/oxygen vs. heavy uranium/lead).

### 1.2 Exchange-Correlation Functional
* **PBEsol Functional:** The revised Perdew-Burke-Ernzerhof functional for solids and surfaces is adopted as the primary functional. PBEsol systematically rectifies the overestimation of equilibrium lattice volumes typical of standard PBE in dense ionic carbonates and actinide oxides.

### 1.3 Projector Augmented-Wave (PAW) Datasets
* **Lead ($\mathrm{Pb}$):** Custom generated semicore PAW (`generated_Pb_PBEsol`) including $5d^{10} 6s^2 6p^2$ valence electrons, validated against elemental FCC lead and cerussite ($\mathrm{PbCO_3}$).
* **Uranium ($\mathrm{U}$):** Scalar-relativistic `U14_nc6` dataset with 14 valence electrons ($6s^2 6p^6 5f^3 6d^1 7s^2$) and 6 partial-wave projectors, validated on $\mathrm{UO_2}$ and $\gamma\text{-}\mathrm{UO_3}$.
* **Host Matrix Elements ($\mathrm{Ca, Mg, C, O}$):** Validated PBEsol PAWs from the GPAW dataset library.

### 1.4 Correlation Correction for Actinides ($DFT+U$)
Strong on-site Coulomb repulsion among localized $5f$ electrons of uranium is treated using the rotationally invariant Dudarev formulation:
$$E_{\mathrm{DFT}+U} = E_{\mathrm{DFT}} + \frac{U_{\mathrm{eff}}}{2} \sum_{\sigma} \mathrm{Tr}\left(\mathbf{n}^\sigma - \mathbf{n}^\sigma \mathbf{n}^\sigma\right)$$
A benchmarked effective parameter of $U_{\mathrm{eff}} = 3.0\text{ eV}$ is maintained across the project, reproducing the experimental lattice parameter and high-pressure bulk modulus of stoichiometric $\mathrm{UO_2}$.

## 2. Supercell Design & Minkowski Lattice Reduction
To avoid severe cell distortion produced by standard diagonal expansions or unconstrained Hermite Normal Form (HNF) matrices, supercells were systematically generated by:
1. Enumerating all unique HNF transformation matrices for determinants 8, 16, and 24.
2. Applying **Minkowski lattice basis reduction** (`minkowski_reduce`) to obtain optimal, maximally compact, and quasi-spherical simulation boxes.
3. Filtering for maximal inter-defect distances ($d_{\mathrm{min}} \ge 10.0\text{ \AA}$ for 80 atoms; $d_{\mathrm{min}} \ge 13.0\text{ \AA}$ for 160 atoms; $d_{\mathrm{min}} \ge 15.0\text{ \AA}$ for 240 atoms).

## 3. High-Performance Execution & Parallelization
* **Domain Decomposition:** Calculations on large supercells distribute real-space grid domains across MPI ranks (`parallel={'domain': 8, 'band': 1, 'kpt': 1}`).
* **Threading Policy:** Strict single-threading per MPI rank (`OMP_NUM_THREADS=1`) to prevent thread contention with ScaLAPACK and BLAS/LAPACK backends.
* **Memory Management:** Memory usage scales with $N_{\mathrm{atoms}} \times E_{\mathrm{cut}}^{3/2} \times N_{\mathrm{bands}}$. On local workstation hardware (~30 GiB RAM), 80-atom cells are accommodated in $\Gamma$-point mode with 4--8 MPI, whereas $\ge 160$-atom supercells require domain decomposition with strict garbage collection or HPC cluster partitions.

## 4. Multi-Tier Execution Architecture & Workload Placement
To guarantee auditability, avoid quota exhaustion, and respect hardware memory bounds, the project enforces a clear multi-tier simulation architecture:
1. **Local Workstation Tier (Strictly Local):**
   * **First-Principles Quantum Mechanics (DFT):** GPAW (Plane-Wave/LCAO) and Siesta calculations are executed exclusively on the local workstation. No ab initio calculations are dispatched to unverified cloud runners.
   * **Classical & Reactive Molecular Dynamics:** LAMMPS simulations (REAXFF, empirical force fields) are executed exclusively on the local machine.
2. **Cloud / GitHub Actions Tier (with Automated Local Migration):**
   * **Machine-Learned Interatomic Potentials (MLIPs) & Analytics:** Python data processing, structure generation, MACE, and CHGNet evaluations can execute within the GitHub repository environment up to available processing thresholds.
   * **Automatic Migration Ceiling:** As soon as GitHub processing limits (time, memory, or runner quotas) are approached, simulation states and checkpoints migrate automatically to continue execution seamlessly on the local workstation.
3. **Institutional Cloud Archival (Google Drive):**
   * Automated mirroring via `scripts/sync_to_gdrive.py` maintains audited, versioned mirrors under the designated agent workspace (`GEMINI-APPLICATIONS/UPb-Carbonate-Geochronology-Petrobras`), ensuring persistent provenance.
